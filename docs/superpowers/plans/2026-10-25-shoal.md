# Shoal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A runnable sandbox demo of Shoal: independent shops join a buying round with a PayPal authorization, an AI agent negotiates the final tier with the supplier inside the supplier's rules, the round closes with a partial capture per shop (or a void), the supplier is paid through Payouts with a holdback, and one shop's delivery claim is triaged by AI and refunded from that holdback.

**Architecture:** Pure, tested money logic in `lib/` (tiers, reservations, captures, holdback, claim limits, the negotiation guard) is the only code that decides amounts. Thin Next.js route handlers call that logic, then thin PayPal and Claude adapters. State lives in an in-memory store seeded with one demo round. The UI ports the brand board's components (round pool, ladder, join stepper, claim card) into React, with AG Grid for allocation and Bryntum (or a CSS fallback) for the timeline.

**Tech Stack:** Next.js 16.4 App Router, React 19.3, Tailwind 4, TypeScript, Node 24 test runner (`node --test`), `@paypal/paypal-server-sdk` 2.5, `@paypal/react-paypal-js` 10.6 (`/sdk-v6`), PayPal Payouts REST, `@anthropic-ai/sdk` with `claude-opus-5-5`, `ag-grid-react`, Bryntum Scheduler (trial), Render.

**Spec:** `PRODUCT.md` (product truth) and `DESIGN.md` (visual system). The brand board `design/brand/index.html` is the reference implementation of the round pool, ladder, join copy, claim card and negotiation layout; port from it, don't reinvent.

## Global Constraints

- All money is integer cents; unit prices are cents per carton. Convert to PayPal strings only in the adapter (`toMoney(25920) === "259.20"`), currency `USD`.
- A shop's price only goes down after it joins: capture is never more than the authorized amount.
- Rules decide, AI coordinates: no price, refund or payout reaches PayPal without passing a function in `lib/round.ts`, `lib/settle.ts` or `lib/guard.ts`.
- Demo round (label it "Demo data" on every surface): supplier **Meadow Oat Co.**, product **Barista oat milk, 1 L carton**, tiers `[{min:0,price:240},{min:500,price:216},{min:1000,price:192},{min:1500,price:180}]`, supplier floor **180**, minimum **96** cartons per delivery, holdback **10%**, round length **3 days**.
- Demo shops, in join order: Hilltop Bakery 240, Little Fern Coffee 180, Northside Deli 96, Corner Books Café 120, Ground Control Coffee 300, Pressed Juice Bar 144, Rye & Co 120, The Daily Grind 240 (total 1,440).
- Claude: model `claude-opus-5-5`, `client.beta.messages.create` with `betas: ["server-side-fallback-2026-07-01"]`, `fallbacks: "default"`, `output_config: { effort: "medium" }`, `tool_choice: { type: "auto" }`, tools with `strict: true`, `max_tokens: 16000`. Check `stop_reason` before reading content. No temperature, no prefill.
- PayPal: sandbox only (`Environment.Sandbox`). Never restyle PayPal buttons. Never use gold, yellow or PayPal blue in Shoal UI.
- Copy: shop-facing word for a void is **Released**; statuses are Reserved, Round open, Captured, Delivered, Claim open, Resolved, Released. Join copy, verbatim: "We'll reserve **{amount}** on PayPal. You'll pay the group price when the round closes, never more. If it doesn't reach its first tier, nothing is charged."
- Design: Berry tokens, Funnel Display 750/700 and Funnel Sans 400/600, one gradient (logo dots and completed fish only), flat never glowing, motion tokens and `prefers-reduced-motion` per DESIGN.md. Live-region announcements for tier changes and round outcomes. WCAG 2.2 AA.
- Secrets only in `.env.local` (gitignored). New env vars go in `.env.example` with empty values.
- Repo goes public with an MIT `LICENSE` at submission (Nov 12, 2026, 12:00 PT).

## Review Focus

1. **Shop joins at a high tier, round ends at a lower negotiated price** → capture is `qty × final`, never above the authorization; saving shown. Test: `capture never exceeds reservation` (Task 1).
2. **Round closes below the first discount tier (under 500)** → every authorization is voided, no capture, shops see "Released". Test: `closeRound voids all when below first tier` (Task 5).
3. **Double submit**: the PayPal approve callback or "Close round" fires twice → one commitment, one capture per shop. Test: `authorize is idempotent per order id` and `close twice captures once` (Task 3).
4. **Claim larger than what is left**: refund requested above the shop's captured amount or the remaining holdback → clamped, and the shortfall is reported, never refunded from another shop. Test: `refund is clamped to holdback and shop capture` (Task 2).
5. **Model output outside the rules**: a price below the supplier floor, above the current tier, non-integer, or malformed tool input → rejected by the guard, never applied; the loop ends after the turn limit. Test: `negotiation rejects below-floor offers and stops at turn limit` (Task 6).

**Out of scope (named, not built):** shipping-cost split between shops (supplier ships each sub-order at its own price), PayPal Invoicing receipts (the in-app receipt stands in), Channel3 retail benchmarks, local-hub delivery, saved payment methods for repeat members, Postgres. Any can be added after Task 13 if time remains.

**Files:**
- Create: `lib/guard.ts`, `lib/guard.test.ts`, `lib/claude.ts`, `lib/gemini.ts`, `lib/agents/negotiate.ts`, `lib/agents/negotiate.test.ts`, `app/api/rounds/[id]/negotiate/route.ts`

**Interfaces:**
- Consumes: `Round`, `tierAt`, `RoundState`, `NegotiationTurn` (Tasks 1, 3)
- Produces:
  - `validateOffer(round: Round, units: number, price: number): { ok: true } | { ok: false; reason: string }` (integer; ≥ `round.floor`; ≤ `tierAt(units).price`)
  - `claude(): Anthropic` in `lib/claude.ts` (reads `ANTHROPIC_API_KEY`), plus `ask(params: { system: string; messages: Anthropic.Beta.BetaMessageParam[]; tools: Anthropic.Beta.BetaTool[] }): Promise<Anthropic.Beta.BetaMessage>` with the Global Constraints settings
  - `negotiate(s: RoundState, model: (side, transcript) => Promise<{ tool: "propose" | "accept" | "walk_away"; price?: number; message: string }>, maxTurns = 6): Promise<{ turns: NegotiationTurn[]; agreed?: number }>`; `claudeNegotiator` is the production `model`.
- Two personas, both Claude: the **shop agent** (knows units, current tier, next tier, shop count; wants the lowest price) and the **supplier agent** (knows its floor, tiers, the 1,500 threshold, and the value of 1,440 committed prepaid cartons). Each turn the model must call one tool: `propose_price {price_cents: integer, message: string}`, `accept_price {price_cents, message}`, `walk_away {message}`. Every proposed or accepted price passes `validateOffer`; a rejected one is recorded with `verdict: "rejected"` and the reason is sent back as the tool result for that side to retry. Agreement = one side accepts the other's last valid price. No agreement → round closes at the tier price.
- Route `POST /negotiate` runs the loop and stores the turns; the UI replays them.
- **Provider config (user request):** `SHOP_AGENT_PROVIDER` / `SUPPLIER_AGENT_PROVIDER` = `claude` | `gemini` (default `claude`). `lib/gemini.ts` mirrors `ask` with `@google/genai` function calling; `negotiatorFor(provider)` picks the adapter; turns record `provider`. Unknown provider or missing key → clear error, no silent fallback.
